# NetBird with UFW-Docker

My reverse proxy needs to be public. PostgreSQL only needs to accept connections from my backup worker over NetBird. I keep the public ports in UFW-Docker and choose which peers can reach the database in the NetBird dashboard.

What tripped me up was seeing the worker’s connection in the UFW-Docker block log even though I’d allowed it in NetBird. NetBird sets a mark on approved packets. A small UFW hook checks that mark, so I can keep managing private services in one place.

<a id="before-you-start" />

## Prerequisites

- A Linux host using UFW and systemd.
- Docker bridge networking with the `iptables` backend and the `iptables-nft` frontend. Check `iptables -S FORWARD` for a jump to `DOCKER-USER`. Docker’s native nftables backend uses a different path.
- NetBird installed as a systemd service on the Linux host, using kernel routing and the `wt0` interface.

The hook below covers IPv4. Run the host commands as root and keep a direct SSH connection or console open. Restarting the NetBird client briefly drops the tunnel, including any SSH session using it.

## How the firewall layers fit together

| Layer | What it controls |
| --- | --- |
| UFW host rules | Connections delivered to the host itself |
| UFW-Docker | Forwarded connections to Docker-published ports |
| NetBird policies | Which peers may reach a peer or resource |

When a peer connects to a port Docker publishes on the host, Docker rewrites the destination to the container’s IP. That’s destination NAT (DNAT). The packet now goes through `FORWARD`. This is why a host `INPUT` rule alone can leave a published port exposed.

UFW-Docker checks these connections in `DOCKER-USER`, before Docker’s own forwarding rules. [Docker firewall chains](https://docs.docker.com/engine/network/firewall-iptables/).

<a id="configure-host-firewall-rules" />

## Allow the public NetBird services

I prefix my containers with `netbird-`, and my Compose network is `netbird_netbird`. Check yours before copying the commands.

```bash
docker ps --format 'table {{.Names}}\t{{.Ports}}'
docker network ls
```

| Port | Service | Exposure |
| --- | --- | --- |
| 80/tcp and 443/tcp | Traefik | Public dashboard, API, relay and HTTPS ingress |
| 3478/udp | NetBird server | Public STUN |

With UFW enabled, keep the host rules your services use.

```bash
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 3478/udp
```

If you serve QUIC on UDP 443, keep that host rule too. Docker also needs to publish each container port you intend to serve. Before removing an existing allowance, check the listener, Docker’s forwarding rules and any IPv6 path you use.

### Install UFW-Docker

For a new install, follow the project’s instructions for the helper and its UFW integration. [Install UFW-Docker](https://github.com/chaifeng/ufw-docker#install).

Once the helper is installed, run these two commands to install its service and load the rules.

```bash
ufw-docker install-service
ufw reload
```

If UFW-Docker is already running, go straight to the container rules. You can add the NetBird hook later without reloading UFW.

<a id="configure-docker-forwarding-rules" />

### Allow the published containers

```bash
ufw-docker allow netbird-traefik 80/tcp netbird_netbird
ufw-docker allow netbird-traefik 443/tcp netbird_netbird
ufw-docker allow netbird-server 3478/udp netbird_netbird
```

Check where Docker sends the traffic and which addresses UFW-Docker allows.

```bash
ufw-docker status
iptables -S DOCKER-USER
iptables -t nat -S DOCKER
docker inspect --format '{{range $name, $net := .NetworkSettings.Networks}}{{$name}} {{$net.IPAddress}}{{"\n"}}{{end}}' netbird-server
```

UFW-Docker stores the container IP in the rule. If a recreated container gets a different IP, rerun its `ufw-docker allow` command and compare the result with the destination in Docker’s NAT rule.

### Optional: NetBird Proxy direct transport

If you use the proxy’s fixed-port direct transport, allow its published UDP port. Otherwise, skip this step.

```bash
ufw-docker allow netbird-proxy 51820/udp netbird_netbird
```

Here I use `NB_PROXY_WG_PORT=51820`. Publish your chosen UDP port in Docker and set `NB_PROXY_EXTERNAL_IP_MAP` to the host’s public address. [NetBird proxy P2P configuration](https://docs.netbird.io/selfhosted/migration/enable-reverse-proxy#enabling-peer-to-peer-connectivity).

## Keep sensitive services private

For PostgreSQL, I publish TCP 5432 on the Docker host so the worker can connect to the host’s NetBird address. I leave 5432 out of the public UFW-Docker rules and set up the following policy in the NetBird dashboard.

1. Put the backup worker’s NetBird peer in the source group.
2. Put the Docker host’s peer in the destination group.
3. Allow TCP 5432 from the source group to the destination group.
4. Check whether another policy or route already grants broader access.

Use the same steps for another private service with its own protocol and published port.

Leave `ufw-docker allow netbird-db 5432/tcp` out of this setup. The helper creates a `from any` allowance, which can open the published database port to the internet.

### Pass NetBird-authorized traffic through UFW-Docker

The worker connects to the host’s NetBird address. NetBird marks the packet on `wt0` while it still has that destination. Docker then changes the destination to the database container. The packet keeps its mark.

If UFW-Docker sees that connection first, it can block the worker even though NetBird allowed it. Here’s what that looks like in the kernel log, using example addresses.

```text
[UFW DOCKER BLOCK] IN=wt0 OUT=br-... SRC=100.64.0.10 DST=172.20.0.10 ... DPT=5432 ... MARK=0x1bd20
```

`IN=wt0` tells you it came over NetBird, `DPT=5432` identifies PostgreSQL, and `MARK=0x1bd20` is the value to check against the live policy. The worker can take this path without selecting an exit node.

On a routing peer, NetBird’s native nftables backend can put a broad `wt0` accept ahead of `DOCKER-USER`. A peer can then reach a published service through a broader route. The iptables backend checks the mark before Docker’s filter rules run. The UFW hook handles the other order, when UFW-Docker sees an approved connection first. A blanket `ufw route allow in on wt0` would also admit traffic without the mark.

## Find NetBird's authorization mark

On the Docker host, run `iptables --version`. Seeing `(nf_tables)` is normal with the `iptables-nft` frontend. To see which rules the NetBird client installed, check the running firewall.

First, run `systemctl cat netbird.service` and look through the existing drop-ins. If the host client already has `NB_SKIP_NFTABLES_CHECK=true`, go straight to the mark lookup below. To enable the iptables backend, create the directory with `install -d -m 0755 /etc/systemd/system/netbird.service.d` if needed. Add the following to `/etc/systemd/system/netbird.service.d/firewall-backend.conf`. This setting goes on the **host NetBird client**. [NetBird client environment variables](https://docs.netbird.io/client/environment-variables#firewall).

```ini
[Service]
Environment=NB_SKIP_NFTABLES_CHECK=true
```

Use your direct SSH connection or console for the restart. Check that management and signal reconnect.

```bash
systemctl daemon-reload
systemctl restart netbird.service
netbird status
```

**Read the mark from the running rules.** The first command shows the jump from `PREROUTING`. The second lists the rules that set the mark.

```bash
iptables -t mangle -S PREROUTING
iptables -t mangle -S NETBIRD-RT-PRE
```

Find the `MARK` rule that matches the permitted peer or source set, your service port and a local destination. On my host the PostgreSQL rule ends like this.

```text
-j MARK --set-xmark 0x1bd20/0xffffffff
```

The value before the slash, **`0x1bd20`**, is the packet mark. The value after the slash is the mask. Use the mark you see on your host in the UFW hook below.

```bash
iptables -S NETBIRD-ACL-INPUT
iptables -t mangle -S FORWARD
iptables -S FORWARD
```

In `NETBIRD-ACL-INPUT`, check that the same source and port have an `ACCEPT` rule. In the filter `FORWARD` chain, look for an accept rule matching the mark you just read. If you use explicit deny policies, also test a new connection from a denied peer. [NetBird peer ACL rules](https://github.com/netbirdio/netbird/blob/6d4814d22726c16961be79409dfbf6a2b2f7537b/client/firewall/iptables/filter_linux.go).

Check that mangle `FORWARD` has these two rules in this order.

```text
-A FORWARD -i wt0 -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT
-A FORWARD -i wt0 -m conntrack --ctstate DNAT -m mark ! --mark 0x1bd20 -j DROP
```

The first lets established connections through this stage. The second drops a new connection if it arrives on `wt0` without the expected mark and Docker has translated its destination. It runs before the filter rules and covers every translated port on that interface. If you also forward other services over `wt0`, test those too. Peers that connect directly to a routed container IP follow a different path and need a separate test. [NetBird forwarding rules](https://github.com/netbirdio/netbird/blob/6d4814d22726c16961be79409dfbf6a2b2f7537b/client/firewall/iptables/chains_linux.go).

## Add the UFW-Docker integration hook

UFW calls `/etc/ufw/after.init` when it starts or reloads. I also have `ufw-docker.service` call the same hook after it refreshes the Docker rules. That keeps a single copy of the exception in `DOCKER-USER`.

Check what’s already installed. The commands below assume the stock `after.init` and no existing `netbird.conf` drop-in. If you’ve customized either file, merge the changes with your own.

```bash
cat /etc/ufw/after.init
systemctl cat ufw-docker.service
ls -l /etc/systemd/system/ufw-docker.service.d/
```

It’s fine if the drop-in directory doesn’t exist yet. Run the remaining install steps in the same root shell. Save the backup path it prints for rollback.

```bash
backup_dir="/root/ufw-netbird-backup-$(date -u +%Y%m%dT%H%M%SZ)"
install -d -m 0700 "$backup_dir"
cp -a /etc/ufw/after.init "$backup_dir/after.init"
iptables -S DOCKER-USER > "$backup_dir/docker-user.rules"
printf 'Backup directory: %s\n' "$backup_dir"
```

Create the hook in the backup directory. Set `NETBIRD_AUTHORIZED_LOCAL_SERVICE_MARK` to the value you read from `--set-xmark` on your host.

```bash
cat > "$backup_dir/after.init.new" <<'EOF'
#!/bin/sh
#
# after.init: if executable, called by ufw-init. See 'man ufw-framework' for
#             details. Note that output from these scripts is not seen via the
#             the ufw command, but instead via ufw-init.
#
# Copyright 2013 Canonical Ltd.
#
#    This program is free software: you can redistribute it and/or modify
#    it under the terms of the GNU General Public License version 3,
#    as published by the Free Software Foundation.
#
#    This program is distributed in the hope that it will be useful,
#    but WITHOUT ANY WARRANTY; without even the implied warranty of
#    MERCHANTABILITY or FITNESS FOR A PARTICULAR PURPOSE.  See the
#    GNU General Public License for more details.
#
#    You should have received a copy of the GNU General Public License
#    along with this program.  If not, see <http://www.gnu.org/licenses/>.
#
set -eu

NETBIRD_INTERFACE=wt0
# Recheck the mark against NetBird's loaded rules after upgrades.
NETBIRD_AUTHORIZED_LOCAL_SERVICE_MARK=0x1bd20

# UFW start/reload and the Docker lifecycle can invoke this concurrently.
exec 9>/run/lock/ufw-netbird-policy.lock
/usr/bin/flock -x 9

netbird_rule() {
    /usr/sbin/iptables -w 5 "$@" \
        -i "$NETBIRD_INTERFACE" \
        -m mark --mark "$NETBIRD_AUTHORIZED_LOCAL_SERVICE_MARK/0xffffffff" \
        -m conntrack --ctstate NEW,ESTABLISHED,RELATED \
        -m comment --comment "NetBird-authorized local service" \
        -j RETURN
}

case "${1:-}" in
start)
    # Do not add firewall state when UFW is disabled.
    if ! /usr/bin/grep -Eq '^[[:space:]]*ENABLED=yes[[:space:]]*$' /etc/ufw/ufw.conf; then
        exit 0
    fi
    # The Docker service post-start hook retries if this chain is not ready.
    if ! /usr/sbin/iptables -w 5 -n -L DOCKER-USER >/dev/null 2>&1; then
        exit 0
    fi
    if ! netbird_rule -C DOCKER-USER >/dev/null 2>&1; then
        netbird_rule -I DOCKER-USER 1
    fi
    ;;
stop|flush-all)
    # Remove only our exact rule, including any historical duplicates.
    while netbird_rule -C DOCKER-USER >/dev/null 2>&1; do
        netbird_rule -D DOCKER-USER
    done
    ;;
status)
    if netbird_rule -C DOCKER-USER >/dev/null 2>&1; then
        echo "NetBird authorized-service forwarding: installed"
    else
        echo "NetBird authorized-service forwarding: absent"
    fi
    ;;
*)
    echo "Usage: $0 {start|stop|flush-all|status}" >&2
    exit 2
    ;;
esac
EOF

sh -n "$backup_dir/after.init.new"
install -o root -g root -m 0750 "$backup_dir/after.init.new" /etc/ufw/after.init
```

The `RETURN` sends a marked connection back to `FORWARD` after `DOCKER-USER`. It applies only to traffic entering `wt0` with the configured mark and one of the listed connection states. UFW-Docker still checks other traffic that enters its chain.

The lock keeps two calls from inserting the rule at the same time. If UFW starts before Docker creates its chain, the service drop-in below calls the hook again once the chain exists.

Add `/etc/systemd/system/ufw-docker.service.d/netbird.conf` and apply the hook.

```bash
install -d -m 0755 /etc/systemd/system/ufw-docker.service.d
cat > /etc/systemd/system/ufw-docker.service.d/netbird.conf <<'EOF'
[Service]
# Reapply after Docker starts and the existing ufw-docker reload finishes.
ExecStartPost=/etc/ufw/after.init start
EOF

systemctl daemon-reload
/etc/ufw/after.init start
/etc/ufw/after.init status
```

`ExecStartPost` runs after the service’s usual start command. Calling the hook directly applies the rule without restarting Docker or reloading UFW.

## Verify the allowed and blocked paths

Run the hook a second time and check its rule and counter.

```bash
iptables -nvL DOCKER-USER --line-numbers
/etc/ufw/after.init start
iptables -S DOCKER-USER
```

Look for one `NetBird-authorized local service` rule ahead of the UFW-Docker checks. Its counter can stay at zero when NetBird accepts the worker’s connection first. Use `iptables -nvL FORWARD --line-numbers` to see the order. During a fresh denied connection that reaches the host, watch the DNAT drop counter with `iptables -t mangle -nvL FORWARD --line-numbers`.

Use a fresh connection for each test. From a peer with netcat installed, run the following command.

```bash
nc -vz -w 3 server.nb.example.com 5432
```

For the public test, use the public IP from outside the overlay. When netcat connects, you know the port is reachable. Database login and permissions are a separate check.

| Source and destination | Expected result |
| --- | --- |
| Peer allowed TCP 5432 → host NetBird address | Connects |
| Actual application client/container → host NetBird address | Connects |
| Peer without that grant → host NetBird address | Blocked |
| External client → host public address, TCP 5432 | Blocked |

I run the worker test from inside the worker container because its network path can differ from the host’s. To check a dashboard change, use a disposable published service. Grant a test peer access and connect. Revoke the grant and open a new connection. The public port should stay blocked in both cases.

Repeat the four checks after a NetBird or Docker restart, a UFW reload or a reboot. Also check the services you already rely on, including public HTTPS, STUN, the reverse proxy and any routes or exit traffic you use. Test IPv6 separately if you use it.

## Troubleshooting and maintenance

<a id="sso-stops-working" />

### Public services or SSO fail

Check DNS, the host listener and Docker forwarding for the OIDC issuer your deployment uses. Substitute your provider’s discovery URL, including its path.

```bash
OIDC_DISCOVERY_URL='https://idp.example.com/.well-known/openid-configuration'
curl --fail --show-error --silent --max-time 10 "$OIDC_DISCOVERY_URL"
docker logs --tail 100 netbird-proxy
docker logs --tail 100 netbird-traefik
```

If sign-in fails in the proxy, run the discovery check from the proxy container as well. A response from the host only confirms the host can reach the issuer. Trace the failing path, including IPv6 if applicable, before opening another port.

<a id="docker-upgrade-connectivity-issues" />

### A Docker update or container recreation changes access

From your direct connection, compare the container’s current IP with the Docker DNAT target and the UFW-Docker allowance. If the allowance still points to an old IP, rerun `ufw-docker allow` for that public service.

UFW-Docker refreshes its rules when Docker starts. An individual container recreation can change an IP between refreshes. The NetBird hook matches the interface and mark, so a new container IP doesn’t require editing the hook.

After a NetBird update, read the mark again and repeat the four access checks. If you change `NB_FWMARK_BASE`, update the value in the hook to match the running rules.

### Roll back the hook

To undo just the backend change, use your direct connection and remove the drop-in you added.

```bash
rm /etc/systemd/system/netbird.service.d/firewall-backend.conf
systemctl daemon-reload
systemctl restart netbird.service
netbird status
```

Check the allowed peer, the denied peer and the public address again. Returning to the previous backend can also bring back the earlier access problem.

If you also want to remove the UFW hook, set `backup_dir` to the path you saved during installation. Stop the hook while the current file is still in place, then restore your backup.

```bash
/etc/ufw/after.init stop
cp -a "$backup_dir/after.init" /etc/ufw/after.init
rm /etc/systemd/system/ufw-docker.service.d/netbird.conf
systemctl daemon-reload
iptables -S DOCKER-USER
```

Remove only the drop-in you created. Restoring the whole saved chain could overwrite other firewall changes. Verify the commented rule is gone, then repeat the connection tests. With the exception removed, UFW-Docker may block approved peers again.
